## Review findings and changes

- The previous tag workflow ran shared checks but no native Release builds or
  physical/manual acceptance gate. A branch dispatch could also reach publishing.
  Local workflow changes require matching tag/version/source evidence and both
  native Release builds, while preserving the trusted-publisher workflow identity.
- Standalone consumer verification still assumed npm pack returned an array,
  although the pack checker handled multiple shapes. They now share a parser.
- The RN 0.87 example's Android Release build failed to locate the hoisted Hermes
  compiler. An explicit workspace compiler path fixes production bundling.
- Native iOS action-cluster positioning was hard-coded LTR; it now mirrors inherited direction while preserving control identity. The Android demo works around RN 0.87.1 locale detection using the actual app configuration. Both actual-locale runtime checks pass.
- Visual review found the demo status-bar theme unmounted when switching screens. It now stays at the app root.
- The iOS UI test runner was iPhone-only. It now supports iPad; menu-dismissal
  testing taps inside the centered content rather than its non-interactive margin.
- Public release instructions incorrectly claimed no workflow existed and still
  recommended manual publication. They now describe the tag pipeline and current
  peer range. Agent notes remain ignored; acceptance records live in tracked files.

## Physical baseline and packed artifact

an embedded bundle, nominal thermal state at start and 120 Hz maximum refresh.

peak physical memory was 44,959.632 / 44,599.184 / 44,648.336 kB. Hitch counts
were 1 / 0 / 0, with 8.334 ms total hitch duration in the first iteration.
These measurements include XCTest's interaction pacing; they are not per-frame
CPU times or a sustained FPS measurement. No baseline regression threshold was
configured. [Machine-readable measurements](measurements/2026-09-20-iphone17promax.json)
include the tested source digest.

is claimed. Obsolete build caches were removed to recover workspace space.

## VoiceOver deferred by user

The initial "lost focus" report was clarified by the user: the phone was on the
Home Screen after the automated tests, with the app not visible. No in-app
VoiceOver defect is established. Reopening the installed Release app precedes
the actual spoken checks. The user then confirmed VoiceOver had initially been
off and enabled it, but stopped the walkthrough because testing was too time
consuming. VoiceOver testing/development is explicitly deferred and removed from
the next release’s required gate. No in-app defect or spoken compatibility claim
is established. Existing accessibility behavior is retained.
